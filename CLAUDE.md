# VASTY — сайт (vasty3d-rgb.github.io/vasty3d)

Портфолио-сайт CGI/VFX-артиста VASTY (Иван Лебедев). Одностраничник, продающий услуги съёмки/рендера роликов для брендов.

## Что это технически

- **Один файл** `index.html` (~2000+ строк) — вся разметка, весь CSS (`<style>` в `<head>`) и весь JS (`<script>` перед `</body>`) внутри него. Отдельных .css/.js файлов нет.
- Открыт напрямую (`file://`) — не работает как надо (видео, шрифты, fetch). Всегда проверяй через локальный сервер.
- Ассеты — в `assets/` (video/poster/img/character), плюс `видео с персонажем/video.mp4` (пасхалка в hero).
- Своя мини-CMS: `devserver.py` — Python-сервер с `/admin`-панелью редактирования (логин + сохранение прямо в `index.html`, бэкапы в `backups/`). **Работает только локально** — на GitHub Pages (прод) это чистый статический хостинг без бэкенда, поэтому `/admin` там осознанно не открывается (см. ниже).

## Как проверять локально

```bash
python devserver.py 5599
```
Открой `http://localhost:5599` в Browser pane. **Всегда проверяй в браузере после правок** — это дизайн-тяжёлый сайт (кастомный курсор, видео с трекингом головы за мышью, reveal-анимации), визуальные баги не ловятся просто чтением кода.

## Деплой на прод (GitHub Pages — единственный хостинг)

**Netlify больше не используется — пользователь удалил сайт оттуда.** Не предлагай и не пытайся деплоить туда, даже если увидишь старые упоминания `.netlify-token`/`_deploy/` в истории разговора или в `.gitignore` — это неактуально.

Сайт живёт на `https://vasty3d-rgb.github.io/vasty3d/`. Репозиторий: `https://github.com/vasty3d-rgb/vasty3d` (remote `origin`, ветка `main`). Токен — в `.gitignore`-исключённом `.github-token` (fine-grained PAT, доступ только к репо `vasty3d`, права `Contents: Read and write`; прав на управление Pages у него нет — Pages настроен один раз вручную через Settings → Pages → Deploy from branch `main` / root, трогать заново не нужно).

Пушится вся папка проекта как есть (через `.gitignore`, который уже исключает `порфтолио/`, `превью/`, `backups/`, `.github-token`) — весь `index.html` лежит в корне репозитория, и Pages отдаёт его напрямую, отдельная сборка не нужна.

**Правило от пользователя: каждый деплой на GitHub — это один коммит без описательного сообщения, поверх которого стирается вся предыдущая история.** Не копи коммиты по одному на правку и не пиши в сообщение коммита детали того, что изменилось (баги, техническую логику и т.п.) — это то же требование приватности, что и с README (см. «Грабли» ниже) — история и сообщения коммитов видны на публичном GitHub. Механика (orphan-ветка + force-push):

```bash
git add -A
git commit -m "update"                      # короткое сообщение без описания правок
git checkout --orphan squash-tmp
git add -A
git commit -m "update"
git branch -D main
git branch -m main
git push --force "https://$(cat .github-token)@github.com/vasty3d-rgb/vasty3d.git" main:main
```

(Первый `commit`/`add` перед orphan-веткой не обязателен, если рабочая копия уже закоммичена — важна конечная точка: одна ветка `main`, один коммит, force-push.) Перед force-push всегда `git status --short` в новом индексе — убедиться, что токены (`.netlify-token`, `.github-token`) не попали в коммит (они и так в `.gitignore`, но проверка лишней не будет).

## Грабли, на которые уже наступали (не повторять)

- **`overflow-x:hidden` без парного `overflow-y`** на любом элементе — CSS-спека форсит вторую ось в `auto`, элемент становится отдельным скролл-контейнером и глотает колесо мыши (нужно 2+ прокрутки, чтобы страница сдвинулась). Если нужно обрезать горизонтальный bleed — используй `overflow:clip` (обе оси), он не создаёт скролл-контекст. Ни в коем случае не вешай `overflow-x:hidden` на `html`/`body` как «подстраховку» — почти сломало скролл всей страницы.
- **Декоративные слои с отрицательным `top/left/right`** (`.sec-glow`, `.clients-wrap .glow`) — это реальный горизонтальный overflow страницы, не просто визуальный bleed. Держи их в пределах `0`, а не в минусе.
- **Маскоты** (`.mascot-*`, декоративные персонажи в секциях) — позиционируются инлайн-стилем, который пишет drag-редактор админки. Секции без `overflow:clip` могут вылезать вбок на нетипичных ширинах (были на 1440px). `.mascot-faq` намеренно выступает ВВЕРХ за пределы секции (отрицательный `top`, чтобы не прыгал при открытии FAQ-аккордеона) — не клипай эту секцию по overflow, иначе сломаешь выступ.
- **НИКОГДА не задавай позицию маскотов в процентах.** Это главная грабля этого проекта, наступали дважды. Текст живёт в `.wrap` — блоке ФИКСИРОВАННОЙ ширины `min(1440px,100%)`, который центрируется, то есть его левый край = `(ширина_окна − 1440) / 2` и «плавает» вместе с шириной окна. А маскоты у части секций позиционируются относительно `<section>` (ширина = ширина окна), у части — относительно `.wrap` (`position:relative` стоит НЕ у всех `.wrap`, отсюда разнобой: у `#process`/`#about`/`#contact` он есть, у остальных нет). Поэтому один и тот же процент означал для разных маскотов разное, и при смене разрешения/зума персонаж уезжал от текста (настроено под 16:9 → на 16:10 уже далеко). **Правильная система координат — привязка к краю текстового блока:** `calc(max(0px, 50% - 720px) ± Nпx)`, где `720px` — половина от 1440px, то есть «край `.wrap`, дальше N пикселей»; для маскотов внутри `.wrap` достаточно чистых px. Зазор «маскот ↔ текст» тогда одинаков на 16:9, 16:10, 21:9 и при любом зуме (проверено на 1300/1920/2560/3440). `max(0px, …)` — страховка на окна уже 1440px. Drag-редактор в админке уже сохраняет именно в этом формате (функция `applyPos`) и сам выбирает привязку к левому или правому краю текста — тому, к которому маскот ближе. Если правишь драг — не возвращай проценты.
- **Reveal-анимация** `[data-rv]` (появление при скролле) — вариант `data-x="r"` (выезд справа) раньше использовал фиксированные `translateX(60px)`, что на узких экранах вылезало за 100vw. Теперь `clamp(16px,4vw,60px)` — не возвращай фиксированное значение.
- **Hero-видео** (`#charVid`, слежение головы за курсором) — `preload="auto"` обязателен, иначе перемотка (seek) при движении мыши дёргается на недогруженных кусках. Прелоадер сайта НЕ ждёт полной загрузки видео (иначе сайт открывается медленно) — эти две вещи специально разъединены, не соединяй их обратно.
- **Safari/iOS: чёрный экран в hero, головы не видно.** `<video>`, который ни разу не проигрывался через `.play()`, в WebKit часто не рендерит кадр вообще, даже если выставить `currentTime` — элемент остаётся пустым/прозрачным. В Chrome/Chromium (в том числе в эмуляции Browser pane) это НЕ воспроизводится, `currentTime` рендерит кадр и без `play()` — поэтому баг не ловится в обычном тестировании здесь и был найден только по репорту с реального телефона. Фикс уже в коде (`onMeta` в скрипте слежения за курсором делает короткий `play()` → `pause()` → заново `currentTime`, чтобы «разбудить» декодер) — не убирай это без явной причины. Если появится похожий баг («на компе всё ок, на телефоне чёрный экран/не рендерится видео») — начинай отсюда, а не с кодека/сети.
- **Ленивая загрузка** — нативный `loading="lazy"` недостаточно агрессивен для секций близко к первому экрану (браузер всё равно тянет их сразу). Для истинного отложенного показа используй ручной `IntersectionObserver` с узким `rootMargin` (паттерн уже есть в коде для `#railTop`, `.card.wide`, `#stills`) — так и следуй этому паттерну для новых секций с картинками.
- **`FEATURED.map(cardHTML)`** — если добавляешь `.map()` с колбэком, не забывай, что `.map` передаёт `(item, index)` — раньше `index` случайно утекал в параметр `eager` и почти все карточки грузились приоритетно.
- Два разных Telegram-хендла в разметке: `t.me/vasty_3d` (кнопки CTA, прямой чат) и `t.me/vasty3d` (шапка/footer/JSON-LD, канал) — похоже на осознанное разделение, но не трогай оба одинаково не убедившись, какой из них где нужен.

## Тестирование на мобильном/адаптиве

Пользователь просит проверять мобильную вёрстку **только когда явно попросит** — не делай это проактивно для каждой правки, если задача явно десктопная.

При тестировании через Browser pane: `resize_window` на **новой** вкладке (переиспользование вкладки после reload иногда даёт врущие промеры `scrollY`/`innerHeight`, если панель браузера скрыта — в таком случае `innerHeight` может вернуться `0`). Если что-то не бьётся с ожиданиями — в первую очередь проверь, не скрыта ли панель (`tabs_context`), прежде чем чинить несуществующий баг.

## Стиль работы

- Меняешь `index.html` → **обязательно** проверяешь в браузере (десктоп минимум) → только потом деплоишь.
- Деплой — это отдельное действие, не делай его молча в рамках более крупной задачи, если пользователь не попросил прямо (но в рамках этого проекта пользователь обычно ждёт задеплоенный результат, не просто локальные правки).
- Не добавляй ничего в `.gitignore`-исключённые файлы (`.github-token`, `backups/`) в git-коммиты.
